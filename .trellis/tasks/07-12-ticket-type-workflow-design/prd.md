# 属性类型工作流功能详细设计

## Goal

为「事项类型配置页」的「工作流」Tab 提供完整的状态机编排能力：
- 从平台状态字典选用/添加状态
- 创建步骤（状态转换 from → to）
- 配置步骤规则（限制权限 / 附加属性 / 更改处理人(预留) / 更改属性值）
- 表格视图与列表视图双模式切换
- 本地草稿自动保存 + 应用配置 + 取消修改

## Background（已确认事实）

### 现有架构
- **前端入口**：`ticket-type-config/index.tsx` → Tabs（属性 / 工作流 / 描述模板）
- **工作流 Tab 组件**：`workflow-tab.tsx` → 内嵌 `TicketTypeFlowDesigner`（将被替换）
- **当前 FlowDesigner**：基于 `@xyflow/react` 的画布式节点编辑器（将弃用）
- **数据模型**（前端 types.ts）：
  ```
  TicketStatusFlowState = { code, name, state_type, allow_customer_withdraw?, is_resolved?, position? }
  TicketStatusFlow = { states: TicketStatusFlowState[], transitions: { from, to, label? }[] }
  ```
- **存储方式**：status_flow 作为 JSON 存在 `ticket_type` 记录中
- **平台状态字典**：独立 CRUD 页面 `/platform/ticket-config/statuses`
  - 后端：`PlatformTicketStatusController` → `TicketStatusService`
  - 实体：`TicketStatusPo`（scope=platform/domain, category=not_started/in_progress/completed）
  - 前端 API：`fetch/create/update/deletePlatformTicketStatuses`
- **域成员/角色 API**：
  - `fetchDomainRoles(domainId)` → `DomainRole[]`
  - `fetchDomainStaffCandidates({ domainId, keyword })` → `DomainStaffCandidate[]`

### 关键差异：当前实现 vs 需求目标

| 维度 | 当前 FlowDesigner | 需求目标 |
|------|-------------------|----------|
| 状态来源 | 画布内自由创建（auto code） | **从平台状态字典选择** + 可跳转新建 |
| 步骤概念 | 无显式步骤，直接连线 | **显式步骤** = from→to 转换，有名称/规则 |
| 规则配置 | 无 | 权限限制 / 附加属性 / 更改处理人(预留) / 更改属性值 |
| 视图模式 | 仅画布 | **列表视图** + **表格视图（矩阵）** 双模式 |
| 操作粒度 | 整体保存 | **本地草稿** + **应用配置** / **取消修改** |

## Requirements

### R1. 状态管理
- [ ] 从平台状态字典选择状态加入工作流
  - 下拉仅显示 active 状态
  - 已添加的状态不可重复添加
  - 支持 Modal 内「前往新建事项状态」链接跳转到字典页
- [ ] 「任何状态可转换到该状态」开关 → 自动为所有已有状态创建到该状态的 transition
- [ ] 移除状态时清理关联的 transitions 和 rules

### R2. 步骤（Transition）管理
- [ ] 创建步骤：选择 from → to（均从已添加到流程的状态中选取）
- [ ] 步骤名称默认 = to 状态名称，可编辑
- [ ] 同一 from→to 组合不可重复创建
- [ ] 删除步骤（同时清理关联 rule 记录）
- [ ] 多种创建入口：顶部「创建步骤」按钮 / 列表行内「+ 创建步骤」

### R3. 步骤规则配置 — 两种入口

#### 入口1：「配置规则」按钮 → Modal（需手动选择步骤）
- 点击工具栏或顶部的「配置规则」按钮
- 弹出 Modal「添加规则」：
  - 规则类型选择器（图标卡片式下拉）：限制步骤权限 / 附加属性 / 更改处理人 / 更改属性值
  - **当前步骤**：Select 下拉，按「开始状态」分组显示，选项格式为 `步骤名称 [from状态Tag → to状态Tag]`
  - 根据规则类型显示对应表单（如选「附加属性」则显示属性选择器）
  - 确定 / 取消

#### 入口2：点击已配置的步骤 → Drawer 侧边抽屉（步骤锁定）
- 在列表/表格视图中点击某个步骤
- 右侧滑出 Drawer「步骤设置」：
  - 顶部固定：**步骤名称**（可编辑）+ **状态转化**（from Tag → to Tag，只读展示）
  - 规则区域：
    - 已配置的规则以卡片形式展示
    - 底部「+」添加规则按钮 → 弹出规则类型选择下拉（图标卡片式，同入口1的风格）
    - 选择类型后直接在 Drawer 内展开该规则的配置表单
    - 空状态提示：「尚未添加规则，点击右上方 '+' 添加规则」
  - 底部：「删除该步骤」按钮
- **Drawer 内步骤（from/to）不可修改**，如需修改步骤本身应删除重建

#### 规则类型详情

| 规则类型 | 平台级可用 | 域级可用 | 说明 |
|---------|-----------|---------|------|
| **限制步骤权限** | ❌ 不可见 | ✅ | 成员列表 / 角色列表，留空不限制。数据源：域角色 + 域成员 |
| **附加属性** | ✅ | ✅ | 执行前必须录入的属性值。数据源：该类型的已配属性槽位 |
| **更改处理人** | ✅（预留UI） | ✅（预留UI） | UI 占位，后端暂不实现 |
| **更改属性值** | ✅ | ✅ | 自动修改属性值。支持所有属性类型（input/select/switch/date），无条件覆盖 |

#### 域级规则继承
- 域级工作流可以看到并使用**平台级已配置的规则**
- 域级可以在平台规则基础上追加域专属规则（如限制步骤权限）
- 平台级规则在域级只读展示（或标记为"继承自平台"），不可在域内删除/修改平台规则

### R4. 视图模式
- [ ] **列表视图（默认）**：
  - 按「开始状态」分组，每组可折叠/展开
  - 组标题显示状态名称 + 颜色标识
  - 组内列步骤：每行显示步骤名称、目标状态（Tag）、用户权限摘要、操作按钮
  - 每组底部「+ 创建步骤」按钮
- [ ] **表格视图（矩阵）**：
  - 行 = 开始状态（Y轴），列 = 结束状态（X轴）
  - 单元格显示步骤信息（有步骤则显示摘要，无步骤显示空白或"+"创建入口）
  - 对角线单元格（同一状态）置灰不可点击
- [ ] 视图切换保持数据一致（共享同一份数据源）

### R5. 数据持久化、撤销与本地草稿
- [ ] **本地草稿自动保存**：
  - 间隔：**5 分钟**一次
  - 存储位置：`localStorage`（key 含 domainId + typeId）
  - 时效：**3 天**，超时自动清除
  - 保存内容：states + transitions + rules 的完整快照（JSON）
  - 页面加载时检测是否有未过期的本地草稿，如有则提示恢复
- [ ] **应用配置**：保存到后端（整体事务）
  - 后端事务内：UPDATE status_flow + DELETE 旧 rules + INSERT 新 rules
  - 成功后清除本地草稿
- [ ] **取消修改**：
  - 优先选项：重新从后端加载全部数据（丢弃本地编辑 + 清除草稿）
  - 备选：恢复到最近一次本地草稿（如果用户确认）
- [ ] **脏数据检测**：
  - 前端 deep compare 当前状态 vs 初始加载状态
  - 未保存时切换 Tab / 离开页面触发提示
  - 标记：保存按钮旁显示「有未保存的更改」文字提示

## Acceptance Criteria

### AC1. 状态管理
- [ ] 可以从平台状态字典选择状态添加到工作流
- [ ] 已添加的状态不会重复出现在下拉中
- [ ] 开启「任何状态可转换到该状态」后，所有已有状态都出现到该状态的 transition
- [ ] 移除状态后，关联的 transition 和 rule 记录被同步清理
- [ ] Modal 中「前往新建事项状态」链接可以正确导航

### AC2. 步骤管理
- [ ] 可以创建 from → to 步骤，步骤名默认为 to 状态名
- [ ] 同一 from→to 不允许重复创建
- [ ] 可以删除步骤
- [ ] 列表视图和表格视图都能正确展示所有步骤

### AC3. 规则配置
- [ ] 入口1（Modal 选步骤）可以正确为任意步骤添加规则
- [ ] 入口2（Drawer 侧边抽屉）可以查看和编辑某步骤的所有规则
- [ ] Drawer 内步骤 from/to 锁定不可修改
- [ ] 4 种规则类型的表单都能正确提交和展示
- [ ] 平台级不显示「限制步骤权限」选项
- [ ] 域级可以看到平台级已配规则并可追加域级规则

### AC4. 视图切换
- [ ] 列表视图和表格视图切换时数据一致
- [ ] 列表视图按开始状态分组，折叠/展开正常
- [ ] 表格视图矩阵正确映射行(x)列(y)到步骤

### AC5. 持久化
- [ ] 本地草稿每 5 分钟自动保存
- [ ] 草稿 3 天后过期清除
- [ ] 页面刷新后可恢复未过期草稿
- [ ] 「应用配置」成功保存到后端并清除草稿
- [ ] 「取消修改」恢复到最后一次后端保存的状态
- [ ] 有未保存更改时离开页面有提示

## 已确认设计决策

### ✅ Q1: 数据模型方案 → **方案 B（步骤规则独立持久化）**
- `status_flow` JSON 仅保留 states + 基本 transitions（from/to/label）
- 步骤规则存为新表 `ticket_transition_rule`，字段含权限/附加属性/属性值变更
- 理由：结构化存储支持查询、外键约束保证完整性、扩展性好

### ✅ Q2: UI 视图方案 → **完全替换 React Flow 画布**
- 弃用 `@xyflow/react` 和 `TicketTypeFlowDesigner` 组件
- 工作流 Tab 全新实现：**列表视图（默认）+ 表格视图（矩阵）** 双模式切换
- 不在首版实现流程图视图

### ✅ Q3: 更改属性值规则细节
- 所有 4 种属性类型（input/select/switch/date）均支持自动赋值
- 一个步骤支持变更多个属性（attribute_updates 为可增减数组）
- 无条件覆盖（直接设为目标值），不支持条件映射

### ✅ Q4: 平台级 vs 域级能力边界
- **平台级可配规则**：附加属性、更改属性值、更改处理人(预留)
- **平台级不可配**：限制步骤权限（角色/成员落实在业务域中）
- **域级可配所有规则类型**（含限制步骤权限）
- **域级继承平台规则**：可以看到平台级已配规则，可追加域专属规则

### ✅ Q5: 保存策略 → **方案 A（整体事务保存）+ 本地草稿**
- 统一「应用配置」按钮，后端事务内完成 UPDATE + DELETE + INSERT
- 「取消修改」→ 重新从后端加载，丢弃本地编辑
- **新增：本地草稿自动保存，5分钟间隔，3天时效，localStorage**

### ✅ Q6: 规则配置交互 — 双入口模式
- **入口1**：「配置规则」按钮 → Modal 弹窗 → 手动选择步骤（下拉按 from 分组，格式 `名称 [from→to]`）→ 选规则类型 → 填写表单
- **入口2**：点击步骤 → Drawer 侧边抽屉（步骤名称+状态转化锁定只读）→ 规则卡片列表 → "+"弹出规则类型选择（图标卡片下拉）→ Drawer 内展开配置
- 规则类型选择器统一采用图标卡片式（限制步骤权限🔒 / 附加属性📋 / 更改处理人👤 / 更改属性值📝）
