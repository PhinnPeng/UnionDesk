# S-00 员工端处理链路端到端人工冒烟

> 2026-08-14 立项，`08-14-employee-handling-chain` 子任务。**前置门禁**：本迭代首个任务。

## Goal

真实浏览器走通员工端两条主链路：**[工单] 队列→领取→处理→变更状态→关闭** 与 **[咨询] 队列→接入→回复→转工单**。目的：暴露"页面存在但实际报错/权限被拒/接口不符/数据不回显"的真实端到端问题，为 EMP1-3 提供定点修复依据。无阻塞项才进入 EMP1-3。

## 现状（勘察核实）
- 工单队列/详情、咨询工作台页面已建并挂路由（`pages/domain/ticket-queue`、`pages/domain/consultations`）
- 后端接口与单测通过；但**前端页面级测试=0，浏览器人工端到端冒烟未做**
- 后端可本地访问（`localhost:8080`）

## Requirements
- R1 冒烟两只环境（客服 agent + 域管理员 domain_admin）视角，逐环节记录实际表现
- R2 覆盖：工单列表筛选/领取/指派/公开回复/变更状态/关闭/合并；咨询列表/回复/转工单
- R3 产出冒烟报告（`agent-work/` 或任务 research/ 目录），每环节标注：通过/阻塞/告警 + 现象 + 复现路径
- R4 阻塞项转成具体修复任务/子项，关联到对应 EMP

## Acceptance Criteria
- [ ] AC1 工单主链路每一环节有明确冒烟记录（通过/阻塞）
- [ ] AC2 咨询主链路每一环节有明确冒烟记录
- [ ] AC3 发现的**阻塞项全部转出**（进 EMP1-3 或独立修复），且不遗留未登记问题
- [ ] AC4 冒烟报告文档化，可追溯

## Constraints
- 不改业务代码；冒烟记录与临时脚本仅放 `agent-work/`（.gitignore）
- 权限/接口问题如实上报，不得算"通过"
