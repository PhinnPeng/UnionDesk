# 侧栏业务域切换与默认偏好

## Goal

在 AdminWeb **业务域端**左侧主菜单底部提供「当前业务域」入口：展示当前域名、点击切换可访问域，并支持设置跨登录默认域；未设置默认时回退可访问列表第一项。

## Background

- 登录后 `AuthService` 将 `defaultBusinessDomainId` 固定为可访问域列表第一项；前端 `auth` store 仅在登录时写入，无事后切换。
- 侧栏结构为 Logo → 菜单 → `SiderTrigger`，尚无全局域切换 UI；平台页内偶发局部 `Select` 与全局会话无关。
- 库中无用户级偏好表；`domain_config` / `system_config` 为可参考的 KV 模式。
- 关联：`07-27-business-console-full-mirror` R3 要求多域成员可切换当前域并重载权限包；本任务落地该交互与默认偏好持久化。

## Confirmed Decisions

| 决策 | 结论 |
|:---|:---|
| 当前 vs 默认 | **分开**：切换改当前会话；设默认写用户偏好，不强制改当前会话 |
| 入口位置 | 业务域端侧栏底部，位于菜单与折叠按钮之间 |
| 列表交互 | 点击底栏弹出 Popover 列表；**默认域置顶** |
| 设默认交互 | 行内 ★/☆；点行主体切换当前域 |
| 持久化 | 后端新建 **`user_config`** 表；key=`default_business_domain_id` |
| 平台侧栏 | **不展示**域切换栏（平台端与业务端职责分离；平台用既有平台入口） |
| 无效偏好 | 配置不在可访问列表内时忽略，回退列表第一项 |
| 切域后页签 | 切换当前域时 MUST `resetTabs` 清空标签页内容，再按新域可达性导航 |
| 列表过滤 | 仅展示用户有权限 **且业务域已启用** 的域；禁用域不进切换列表 |

## Requirements

### R1 — 展示当前业务域

- 业务域端侧栏 MUST 在底部展示当前业务域名（展开态可读文字；折叠态可用图标 + Popover）。
- 数据源 MUST 为当前会话活跃域（JWT / session 中的 `businessDomainId`，与前端 current 域一致）。

### R2 — 切换当前业务域

- 用户点击底栏 MUST 打开可访问且**已启用**的业务域列表（禁用域 MUST NOT 出现在列表中）。
- 点击某一行 MUST 将该域设为当前会话域，并重发/更新会话令牌中的域上下文。
- 切换后 MUST：① `resetTabs` 清空当前标签页内容；② 按新域重拉 business 权限快照与菜单；③ 若当前路由在新域菜单中不可达，MUST 回退业务首页。
- 仅可访问且启用的域可切换；服务端 MUST 校验成员关系与域启用状态，不得仅信前端传参。

### R3 — 设置默认业务域

- 列表行内星标 MUST 可将该域设为默认偏好，写入 `user_config`。
- 设默认 MUST NOT 强制切换当前会话域（除非产品后续改口）。
- 列表 MUST 将默认域置于顶部，并标明「默认」。
- 下次登录 / 新会话解析当前域时 MUST 优先使用有效默认偏好；无偏好或无效时 MUST 使用可访问列表第一项。

### R4 — 布局覆盖

- MUST 接入标准侧栏、mixed 侧栏；移动端抽屉须有等价入口。
- `/platform/*` 平台控制台 MUST NOT 展示该切换栏。

### R5 — Out of Scope

- 客户门户域切换（已有独立模式）
- 跨设备以外的「最近访问域」历史列表
- 平台端跨域管理入口改造
- 将 `defaultBusinessDomainId` 字段从登录响应中物理删除（可先语义拆分前端字段，后端响应可渐进兼容）

## Acceptance Criteria

- [ ] AC1 业务域端侧栏底部可见当前业务域名；平台端侧栏无该入口
- [ ] AC2 点击底栏弹出列表；默认域（若有）置顶并标「默认」；列表不含禁用域
- [ ] AC3 点行切换后：标签页清空；会话/JWT 域 ID 更新；菜单与权限按新域加载；不可达路由回退首页
- [ ] AC4 点星标后重登（或新会话）落在该默认域；清掉/无效配置后落在可访问且启用列表第一项
- [ ] AC5 对不可访问或已禁用 `domainId` 的设默认/切换请求被服务端拒绝
- [ ] AC6 展开/折叠/移动端均可完成切换与设默认
