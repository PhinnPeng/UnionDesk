# 事项类型配置页 — 属性 Tab 布局优化

## 背景

平台「事项类型配置 → 属性」页当前与 Coding 参考页、菜单/列表模块风格存在差距：列宽不均、Header 无层次、缺少搜索块、表格未用 Card 容器。

## 目标

在 **不改变业务逻辑**（draft/发布、DnD 排序、编辑/删除、属性排序抽屉）前提下，统一布局与交互风格。

## 范围

- **仅** `layout="platform"` 的属性 Tab
- 涉及 Header（面包屑 / 标题卡 / Tab）+ AttributeTab 内容区 + 表格列宽与操作列

**不在范围**：工作流 Tab、描述模板 Tab、域内 legacy 布局、后端 API

## 验收标准

### Header

- [ ] 面包屑：返回箭头与文字链接 hover 一致（颜色 + 浅底圆角）
- [ ] 事项类型块：白底 + 细边框 + 轻阴影，与 Shell 背景有层次、不突兀
- [ ] Tab：与标题区结构协调，去掉负边距 hack，激活下划线清晰

### 搜索

- [ ] 增加 `Card`「筛选条件」+ `TableSearchForm`，关键字字段 label「关键字」
- [ ] 前端过滤：匹配属性名称、描述、**含系统固定行**（标题/描述等）
- [ ] **始终展示**「以上属性不可排序」分隔行（有固定行时）
- [ ] 搜索非空时 **仍允许** 表格内拖拽排序

### 列表区

- [ ] 采用 `Card`「属性列表」+ `extra` 放置「属性排序」「添加属性」（对齐菜单/域列表工具栏位置）
- [ ] 表格保留现有 `AttributeSlotTable` + DnD，不迁移 BasicTable
- [ ] 表头/行样式与菜单模块 Card 内表格观感一致

### 列宽

- [ ] 各列宽度合理，`tableLayout="fixed"`
- [ ] 操作列：**文字 + 图标**（编辑、删除），列宽足够不挤压

### 质量

- [ ] `pnpm run typecheck:admin` 通过
- [ ] 关键交互冒烟：搜索、拖拽、编辑、删除、暂存/发布

## 用户确认决策（2026-07-10）

| # | 决策 |
|---|------|
| 1 | 过滤时始终展示分隔行；固定行纳入搜索，不单独做「始终置顶」逻辑 |
| 2 | 搜索后同样允许拖拽 |
| 3 | 列表区采用 Card + Table（非 BasicTable） |
| 4 | 操作列采用「文案 + 图标」 |
