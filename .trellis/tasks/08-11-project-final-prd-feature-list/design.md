## 2. 编号体系（唯一来源：prd.md §4.2）

- 模块：M1 客户端 / M2 员工端（作业台）/ M3 域管理后台 / M4 平台管理后台 —— 沿用现有 M/F 编号，新增功能在模块内续编（如 F1.6 登录、F1.7 注册…）
- `feature-list.md` 每行复用同一编号，两文档双向可追踪
- 端侧归属映射（research 阶段以代码路由核实）：
  - **客户端**：M1 全部 + 新增（登录/注册/个人中心/站内信等）
  - **管理端-平台端**（`/platform/*`）：M4 + IAM 治理（用户/角色/菜单/部门/审计/登录日志/全局屏蔽词/离职池/导入导出）+ 平台工单池 + 表单设计器
  - **管理端-业务域端**（根级/域上下文）：M3 全部 + M2 员工工作台（工单处理、在线咨询）+ 域内配置（工单类型/团队模板/客户/成员/角色/屏蔽词/通知/审计/入域）

## 3. 双端表结构（feature-list.md）

```
feature-list.md
├── 1. 总览与图例（状态术语、端侧缩写、统计摘要、状态基准日期）
├── 2. 最终功能清单（全量：编号|模块|功能|端侧|优先级|状态，一表全貌）
├── 3. 客户端功能清单表（CustomerWeb，10 列）
├── 4. 管理端功能清单表（AdminWeb：4.1 平台端 / 4.2 业务域端，10 列）
└── 5. 功能清单说明（按模块叙述：目的、主要能力、关键规则引用 foundation-rules / prd.md 章节）
```

10 列：`功能编号 | 端侧 | 模块 | 功能 | 功能说明 | 优先级 | 实现状态 | 对应页面/路由 | 关联 Epic/Story | 备注`

- 粒度：页面功能级（每行 = 一个页面级能力；按钮级细节并入功能说明）
- 优先级：沿用 P0/P1/P2
- 实现状态：已实现（Done）/ 部分（Partial）/ 规划中（Todo/未排期）；不确定性标「待联调确认」
