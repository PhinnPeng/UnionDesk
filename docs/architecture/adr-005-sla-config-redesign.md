# ADR-005：SLA 配置重构 —— 域内单配置面板（取代双层规则列表）

> 状态：**已采纳**（2026-08-16 拍板：D1 域内自配置平台不管理 / D2 紧急后置 / D3 升级固定+两动作动态 / D4 日历三要素 / D5 单份通配 / D6 内嵌单日历 / D7 平台隐藏 / D8 新表承载 / D9 升级开关+目标档 / D10 FieldTimeOutlined / D11 更名 SLA 配置） · 关联：[ADR-002 双层配置](adr-sla-two-tier-config.md)（**D1-D3 被本 ADR 取代**）、[ADR-003 实时消息](adr-realtime-websocket.md) · 设计说明：[sla-config-redesign.md](../product/sla-config-redesign.md)

## 1. 背景

SLA 管理现状被判定「非常模糊」：双层规则列表（全局+域代管）对普通域管理员过度复杂；工作日历（sla_calendar）与紧急配置（is_urgent_config）是零消费死能力；菜单无图标、平台菜单图标未注册；域页与平台页双入口职责重叠。需求：SLA 降级为**业务域内自配置**的固定面板（平台不管理），重新设计为清晰可用的配置页。

## 2. 决策

1. **域内自配置，平台不管理**：域端 `/domain/sla` 为唯一配置入口；平台 SLA 菜单隐藏（hidden=1），页面/接口/权限码保留不删（D1/D7）。
2. **单份通配配置**：域内仅一份 SLA 配置（首次响应/解决响应/超时动作/工作日历），作用于该域所有工单；不再按事项类型/优先级拆分规则列表（D5）。
3. **超时动作 = 固定块 + 动态块**：升级优先级为固定块（开关 + 目标档下拉，取代仅按序升）；更换处理人（MemberPicker 单选）/添加关注人（MemberPicker 多选）为动态块，右上「添加动作」下拉追加、可多可删；执行顺序固定：升级优先级 → 更换处理人 → 添加关注人，每工单仅一次（D3/D9）。
4. **工作日历三要素 + 引擎接入**：工作日（周几复选，默认一~五）/ 周末是否工作（开关）/ 节假日（日期列表）；deadline 按工作分钟折算（跳过周末与节假日），接入 applyOnCreate 与 SlaScanJob（D4）。
5. **新表承载**：新建 `sla_config` 单行表（uk_sla_config_domain），旧 sla_rule/sla_calendar 保留不读兼容回滚（D8）。
6. **紧急配置后置**：数据模型预留 urgent_* 列，UI 本轮不显示（D2）。
7. **菜单更名 + 图标**：「SLA 管理」→「SLA 配置」，icon 回填 FieldTimeOutlined 并注册 menuIcons（D10/D11）。

## 3. 被否决的替代方案

- **保留双层规则列表（仅优化表单）**：与「非常模糊需重新设计」诉求不符，域管理员仍面对类型/优先级矩阵，否决。
- **平台端唯一入口**：SLA 是业务域运营能力，平台统一管理反而让域自治退化（用户明确：仅业务域内自配置），否决。
- **平台端彻底删除**：不可逆且全局兜底能力消失；隐藏保留成本极低（D7 折中），否决。
- **改造 sla_rule 为单行**：破坏旧表结构与旧接口，回滚困难；新表隔离更稳（D8），否决。
- **日历多套可选**：单份通配配置 + 多套日历语义冗余（一套配置只能挂一套），内嵌单日历最简（D6），否决。

## 4. 后果

- **有利**：配置心智大幅简化（一份配置 = 三区字段）；工作日历首次真正参与计算；域自治完整（平台不介入）；旧数据零迁移可回滚；升级目标可选档位比「仅按序升」更可控。
- **代价**：新表 + 新接口（GET/PUT sla-config）；loadPolicy 需支持新旧双路径（过渡期）；引擎需实现日历折算（工作分钟）；`escalate_priority` 从 bool 升级为对象需兼容旧值；平台菜单隐藏后按钮码不一致问题（platform.domain.control.overview vs platform.sla.*）顺带暴露，本期仅隐藏不清理。
- **边界**：紧急配置（urgent_*）后置；平台全局兜底能力本期停用（菜单隐藏）；旧域规则数据不再参与匹配（新配置优先，旧链仅兼容回滚）；「即将超时」高亮仍属 E-EMP3 范畴，不在本 ADR。
