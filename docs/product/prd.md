## 二、背景与目标

### 2.1 背景

- 企业多品牌/多业务线并行运营，客户服务入口分散，工单与咨询数据无法统一治理。
- 各业务线对权限隔离、SLA、表单配置诉求不同，缺乏可复用的中台能力。

### 2.2 产品定位

UnionDesk 是一个企业级、多业务域、可配置的客户服务中台。它帮助企业统一管理**工单、在线咨询、反馈建议**三类服务请求，通过「业务域」实现不同品牌/业务线的独立运营与权限隔离。

### 2.3 核心价值

- **多业务域完全隔离**：一套系统，管理多个独立品牌，互不干扰。
- **统一身份，两端分离**：一个账号主体，可同时是 A 业务的客户、B 业务的客服。
- **动态工单表单**：各业务域可自定义工单字段和状态流程。
- **完整服务闭环**：在线咨询 → 转工单 → SLA 保障 → 满意度评价。

## 三、故事介绍

### 3.1 场景描述

- 客户在某业务域提交工单，填写动态表单，获得工单号并跟踪处理进度。
- 客户进入在线咨询窗口排队，接入客服后实时聊天，会话可一键转为工单。
- 客户在工单关闭或咨询结束后，通过通知中心完成星级与文字评价。
- 客服在工单队列中按域、状态、优先级、SLA 筛选并处理分配给自己的工单。
- 客服从咨询队列手动接入客户，聊天中可撤回 2 分钟内消息，并将会话转为工单。
- 域管理员使用低代码表单设计器配置工单类型、SLA 规则与通知模板。
- 域管理员管理本域成员、客户与自定义角色权限组合。
- 平台管理员创建/管理业务域，设置可见与注册策略，治理全局员工与安全策略。

### 3.2 价值分析

- 多业务域隔离使一套中台支撑多品牌独立运营，降低重复建设成本。
- 统一身份 + 两端分离，减少客户与员工账号割裂带来的体验与运维成本。
- 动态工单表单与 SLA 配置，使各域可按自身流程交付服务而不改代码。
- 咨询 → 工单 → SLA → 评价的闭环，提升服务可追踪性与满意度数据沉淀。

### 3.3 用户核心路径

**客户端主路径**

选择业务域 → 提交工单 / 进入在线咨询 → 等待处理 / 排队接入 → 查看进度 / 继续沟通 → 确认解决 → 满意度评价

**员工端主路径**

登录员工端 → 查看工单队列 / 咨询队列 → 领取或接入 → 处理（回复/转派/变更状态）→ 关闭工单 / 结束咨询

**域管理后台主路径**

进入本域 → 配置工单类型与 SLA → 管理成员与客户 → 分配角色权限

**平台管理后台主路径**

创建/管理业务域 → 管理全局员工与平台角色 → 配置全局安全策略与告警

| 漏斗   | 步骤             | 转化率指标 | 目标值                   |

## 四、概要设计

### 4.1 架构约束（全局设计决策）

#### 4.1.1 统一身份模型

- **一个身份主体**：`identity_subject` 是系统中自然人的唯一标识。一个手机号对应一个主体。
- **两种账号**：一个主体下，可同时拥有 `staff_account`（员工账号）和 `customer_account`（客户账号）。
- **登录与切换**：客户端和员工端分别登录，底层共享认证会话。若同一主体已登录员工端，打开客户端时可免密切换。
- **客户入域**：客户账号需加入某业务域后才能访问该域服务。入域方式由业务域的注册策略控制。

#### 4.1.2 多业务域隔离

业务域是资源隔离的基本单元。每个业务域拥有独立的工单、咨询、人员、配置。


| 策略类型     | 选项                          | 说明          |
| :-------- | :--------------------------- | :----------- |
| **可见策略** | `公开` / `仅域内客户可见` / `仅渠道可见`  | 控制谁可以发现这个域  |
| **注册策略** | `开放注册` / `仅邀请注册` / `仅管理员添加` | 控制客户如何加入这个域 |


#### 4.1.3 权限体系

平台采用 **「平台角色 + 业务域角色」双层权限**。单个角色 MUST 仅绑定一种控制台（`role.scope = global` 或 `domain`），不得在同一角色内混合 platform 与 business 权限包。

- **平台级**（`role.scope = global`，仅平台管理后台）：
  - `platform_admin`：日常平台运维，创建业务域、管理全局员工等。
  - `super_admin`（global）：break-glass 应急角色，权限包与 `platform_admin` 同为纯 platform 控制台能力；**不在用户管理 UI 中作为可分配角色**。
- **业务域级**（`role.scope = domain`，仅域管理后台）：每个业务域内置三个角色。
  - `super_admin`（domain）：域最高权限，管理域内一切。
  - `domain_admin`：管理域内常规配置与人员。
  - `agent`：基础客服，处理工单、接待咨询。
  - *域管理员可基于「权限项」组合创建最多 20 个自定义角色。*
- **双控制台用户**：若同一人需同时使用平台与业务域控制台，须通过 **显式组合绑定**（`user_global_role` + `user_domain_role`）实现，不得用单个 global 角色内嵌 business 直授模拟。
- **权限项**：精确到按钮的功能权限，格式为 `模块:操作`，如 `ticket:delete`。数据范围通过 `:self` / `:domain_all` 后缀控制。

##### 集团统一管理职责矩阵（目标态）

> 目标态：平台统一管理（用户 / 角色模板 / 跨域批量停用）+ 域内实例微调（锁定字段约束），详见任务 `08-11-group-role-management`；依赖 **US-S1-08**（目标域校验，**P0 前置安全债**，未完成前不得启用模板/批量 API）。

| 能力 | 平台端 | 业务域端 |
| :--- | :--- | :--- |
| **用户 / 成员** | 全局员工库全权（创建/停用/离职）；**跨域批量停用（step-up 二次认证）** | 成员日常运营（本域成员添加 / 角色调整 / 启停） |
| **角色** | 角色模板（`role_template`）创建 · 下发 · 同步（一次 apply 多域生成各域实例） | 角色实例微调（**锁定字段除外**；锁定字段默认权限包） |
| **治理与配置** | 审计监管（跨域可追溯）+ break-glass | 域配置自治（工单类型 / SLA / 客户 / 屏蔽词等） |

- 冲突裁决：双端对同源数据可写，冲突以「锁定字段 + 同步策略（默认 immediate）」为准；跨域写一律逐域鉴权（US-S1-08）。

#### 4.1.4 全局安全策略

- **认证**：JWT + Refresh Token 轮换，支持单账号多会话踢除。
- **安全屏蔽**：全平台统一敏感词库，命中即拦截并告警。
- **审计**：所有管理操作、状态变更、权限修改均写入 `audit_log`，不可删除。

## 五、详细设计

### 5.1 客户端（用户视角）

*客户端是用户寻求帮助的统一入口。*

#### 5.1.1 服务请求

- **提交工单（F1.1）**：用户选择工单类型（问题/反馈/建议），填写动态表单，提交后获得工单号。反馈/建议类型可在域内预置为简表单工单类型，由管理员在工单类型设计中启用/停用（见 Backlog E2/E3）。
- **在线咨询（F1.2）**：用户进入咨询窗口，先排队，接入客服后可实时聊天。可发送文字、图片、附件。
- **反馈/建议（F1.3）**：**MVP 以工单类型路径交付**；独立轻量入口（三态展示）为可选形态，纳入下期规划，不与工单类型开关拆成两套后台模块。

#### 5.1.2 服务跟踪

- **我的工单（F1.4）**：查看提交过的所有工单，查看客服公开回复，补充信息，确认解决后评价。
- **咨询历史（F1.4）**：回看历史聊天记录和关联工单。
- **满意度评价（F1.5）**：工单关闭或咨询结束后，用户可在通知中心找到评价入口，进行星级+文字评价。

#### 5.1.3 账号与入域

- **登录（F1.6）**：账号/密码登录（真实 API），接入滑块验证（后端 challenge，5 秒过期缓冲）；支持记住账号、专属域入口（`/d/:domainCode/login`）、新环境登录站内提醒。忘记密码当前为占位提示。
- **注册与入域（F1.7）**：注册表单（显示名/登录名/手机号/密码/邮箱可选）+ 开放域下拉 + 邀请码；专属域注册预填邀请码。注册与邀请码入域当前为本地演示（mock），接真实 API（`/api/v1/auth/register`）见 US-S3-02。
- **业务域选择与切换（F1.8）**：以「已加入 / 可加入 / 需管理员开通」三组卡片展示业务域，支持切换当前域（真实 switch-domain API）；未入域客户不可访问域能力（FR-05）。

#### 5.1.4 首页与通知

- **服务首页（F1.9）**：问候语、待处理提醒、生命周期统计卡（待处理/进行中/已完成）、最近 5 条工单、未读通知前 3 条（jumpUrl 跳转）。
- **站内信 / 通知中心（F1.10）**：站内信列表（system/ticket/domain 分类）、未读数、标为已读、按 jumpUrl 跳转查看。

#### 5.1.5 个人中心

- **个人中心（F1.11）**：账号信息（显示名/登录名/手机号）、业务域与通知入口、退出登录（真实 API）。通知偏好当前为占位（邮件/站内信开关即将上线）。
- **修改密码（F1.12）**：当前密码/新密码/确认，前端校验（新密码 ≥6 位、两次一致、不与当前相同）；`mustChangePassword` 强制改密；成功后回登录页。

### 5.2 员工端（客服视角）

*客服在此处理分配给自己的工作。*

#### 5.2.1 工单处理中心

- **工单队列（F2.1）**：按域、状态、优先级、SLA 状态筛选工单。支持批量领取、批量关闭。
- **工单详情（F2.1）**：左侧时间线（公开回复、内部备注、系统操作），右侧属性卡（状态、优先级、SLA 倒计时）。
- **处理动作（F2.1）**：公开回复、内部备注、转派他人、变更状态、请求客户补充信息。
- **SLA 感知（F2.2）**：列表页和详情页高亮显示 SLA 即将超时或已超时的工单。

#### 5.2.2 在线咨询工作台

- **接待（F2.3）**：客服手动从队列中接入等待的客户。
- **聊天（F2.3）**：实时收发消息，支持撤回 2 分钟内的消息。
- **转工单（F2.3）**：一键将当前会话转为工单，自动带入客户信息和会话摘要。

#### 5.2.3 业务域端工作台

- **业务域端首页 / 工作台（F2.4）**：展示当前业务域与概览说明，快捷入口按权限过滤（`scope=business` 菜单）；域内员工（`agent`/`domain_admin`）登录后默认进入（US-S2-E2-00 三元规则）。

### 5.3 域管理后台（管理员视角）

*域管理员在此配置本业务域的规则与人员。*

#### 5.3.1 域配置

- **工单类型设计（F3.1）**：使用低代码表单设计器创建/编辑工单类型，配置其动态字段和状态流程。
- **SLA 规则（F3.2）**：配置本域默认 SLA 和按工单类型的特殊 SLA（首响/解决时限、违约动作）。
- **通知模板（F3.2）**：编辑各类事件（工单创建、SLA 预警等）的站内信和邮件模板。
- **事项属性与状态配置（F3.4）**：域内事项配置三面板（类型/属性/状态，复用平台面板）；属性插槽支持拖拽排序、编辑显示名/占位符/默认值，系统属性锁定不可删（US-S3-01a）。
- **入域配置（F3.6）**：域端入域管理，维护邀请码与注册策略双开关。
- **域基础设置（F3.7）**：维护域名称、LOGO、描述等基础信息。
- **域参数配置（F3.8）**：KV 键值对配置（key/value/valueType/description）。
- **域屏蔽词库（F3.9）**：维护本域词条（增删查、重复提示、空态）；词条去首尾空格，禁止空词。
- **域通知配置（F3.11）**：通知相关配置（当前为占位页，菜单与权限已就绪）。

#### 5.3.2 人员与权限

- **成员管理（F3.3）**：从平台员工库中添加/移除本域成员，并分配角色。
- **客户管理（F3.3）**：查看本域客户列表，手动激活/禁用，打标签。
- **角色管理（F3.3）**：创建自定义角色，勾选所需的权限项组合。
- **域客户管理增强（F3.5）**：在 F3.3 基础上支持客户编辑、重置密码、从员工导入、只读详情（真实 API）。
- **系统角色管理（F3.13）**：域端角色列表/创建/编辑（权限树）/删除，`scope=domain`。
- **系统菜单管理（F3.14）**：域端菜单树 CRUD，`scope=business` 筛选。
- **系统用户管理（F3.15）**：域端用户管理（当前为模板遗留占位页）。
- **系统部门管理（F3.16）**：域端部门管理（当前为模板遗留占位页）。

#### 5.3.3 域数据与运营

- **域运营概览（F3.10）**：域内运营统计（4 项 Statistic + 趋势）；统计值当前为「—」、趋势「数据接入中」（部分实现）。
- **域级操作日志 / 登录日志（F3.12）**：查看本域操作日志与登录日志，支持分页与时间/结果/关键词筛选；审计日志不可删除。

### 5.4 平台管理后台（系统视角）

*平台管理员在此进行跨域的全局治理。*

#### 5.4.1 业务域管理

- **创建/管理（F4.1）**：新建业务域（从模板或空白），设置其可见与注册策略，启用/禁用。
- **模板中心（F4.2）**：将某个域的完整配置提炼为模板，供快速创建新域。
- **域配置 KV（F4.19）**：平台侧维护业务域 KV 键值对配置（key/value/valueType/description）。
- **客户入域邀请码面板（F4.20）**：平台侧维护业务域邀请码（CRUD）；CustomerWeb 接真实入域 API 见 US-S3-02（部分实现）。

#### 5.4.2 员工与权限管理

- **员工账号（F4.3）**：全局员工列表，手动创建或 CSV 批量导入。分配平台角色，或将其加入指定业务域并赋予域角色。
- **离职池（F4.3）**：员工账号删除后进入离职池，其名下的未关闭工单自动退回队列。
- **用户管理（F4.7）**：平台用户列表/搜索（用户名/账号/手机/邮箱）+ 部门树侧栏筛选 + 状态 Tag；创建/编辑/离职/重置密码（随机 16 位展示复制）；永久删除无前端入口。
- **组织 / 部门管理（F4.8）**：组织部门树 CRUD，支持搜索、循环引用检测、删除子部门校验。
- **角色管理（F4.9）**：角色列表（scope 筛选 platform/domain）、创建/编辑（菜单+按钮权限树）、删除（禁止删除预置角色）；保存时 scope 不一致拒绝 + 中文提示（US-S3-00）。
- **菜单管理（F4.10）**：菜单树 Table（scope 筛选 platform/business）、创建/编辑（图标选择器、菜单/按钮节点）、删除（级联子菜单）。
- **权限管理入口（F4.11）**：权限管理页当前重定向至角色管理页（部分实现）。
- **用户导入导出（F4.18）**：用户批量导入导出（当前为占位页，API 待完善）。
- **组织配置（F4.21）**：组织架构配置页（当前为占位页）。

#### 5.4.3 系统设置与安全

- **全局安全策略（F4.4）**：密码强度、登录失败锁定、IP 白名单。
- **安全告警中心（F4.4）**：查看和处理所有派生的安全告警（如暴力破解、高频操作）。
- **审计日志 / 登录日志（F4.12）**：平台统一页（审计/登录 Tabs）+ 独立页双入口；操作日志、登录日志可分页筛选；审计日志不可删除；独立页与统一页功能重叠，建议收敛。
- **全局屏蔽词（F4.13）**：平台全局敏感词库 CRUD，跨域生效（`business_domain_id` 为空）。

#### 5.4.4 工单与消息（平台侧）

### 6.1 数据分析 / 埋点设计

> 埋点 Code 采用 `小写下划线` 命名规范（如 `ticket_submit`），与 Action 一一对应；下表 Code 为**命名规范占位**，具体埋点值与埋点平台统一在**验收期回填**。


| Action  | View     | Code                   | 说明         |
| :------- | :-------- | :---------------------- | :---------- |
| 提交工单    | 客户端-提单页  | `ticket_submit`        | 对应漏斗：提单提交率 |
| 进入在线咨询  | 客户端-咨询窗口 | `consult_enter`        | 对应漏斗：接入转化率 |
| 客服首次响应  | 员工端-工单详情 | `agent_first_response` | 对应漏斗：首响达标率 |
| 关闭工单    | 员工端-工单详情 | `ticket_close`         | 对应漏斗：解决关闭率 |
| 完成满意度评价 | 客户端-评价入口 | `satisfaction_submit`  | 对应漏斗：评价参与率 |


**数据报表需求（待确认，验收期回填）**

- 按业务域维度的工单量、SLA 达标率、评价分布
- 咨询接入时长、会话转工单比例

### 6.2 非功能要求

- **性能**：工单列表常用查询 P95 &lt; 1s。
- **安全**：全站 HTTPS，密码 Argon2 哈希，JWT 认证。
- **终端**：客户端/员工端需响应式适配手机、平板、桌面端。
- **浏览器**：支持 Chrome/Edge/Firefox/Safari 最近两个主版本。

### 6.3 核心验收标准

- **核心闭环**：至少 3 个业务域下，客户提单 → 客服处理 → 客户查单的流程可闭环。
- **权限隔离**：A 域客服不能看到 B 域工单；自定义角色只能访问被授权的菜单和按钮。
- **安全验证**：关键操作（删除域、全量导出）需密码二次验证，并写入审计日志。
- **SLA 验证**：可配置工作日历，SLA 计时准确，临近/超时预警正常触发。
- **环境交付**：提供一键 `docker-compose.yml`，可跑通全部 P0 验收用例。
